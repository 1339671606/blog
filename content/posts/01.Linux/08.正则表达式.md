# 正则表达式

正则表达式（Regular Expression，简称 regex / RE）用来描述一类文本的结构

一条正则只说明“匹配什么”，真正执行匹配的是 grep、sed、awk、Bash 等宿主程序，结果如何输出由工具决定

## 先看懂一条正则

从一行文本里提取所有连续数字

```bash
printf '%s\n' 'user123 order456' | grep -oE '[0-9]+'
# 123
# 456
```

| 部分        | 含义                |
|:--------- |:----------------- |
| `[0-9]`   | 匹配一个数字            |
| `+`       | 前一个单位连续出现一次以上     |
| `[0-9]+`  | 一段连续数字            |
| `grep -E` | 使用扩展正则表达式，简称 ERE  |
| `-o`      | 只输出匹配到的片段，每个片段占一行 |

去掉 `-o`，输出变回整行，匹配规则没有任何变化

```bash
printf '%s\n' 'user123 order456' | grep -E '[0-9]+'
# user123 order456
```

## 选择正则方言

同一符号在不同正则方言中的含义可能不同，先确认工具使用的方言，再决定模式怎么写

| 工具 | 正则方言 |
|:---|:---|
| grep、sed | 默认 BRE，`-E` 切换到 ERE |
| GNU grep | 还可用 `-P` 使用 PCRE |
| awk、Bash `[[ =~ ]]` | ERE |
| find | 默认 Emacs 正则，可用 `-regextype posix-extended` 切换到 ERE |

本文未特别说明时，语法示例使用 ERE

| 功能 | BRE | ERE | PCRE |
|:---|:---|:---|:---|
| 0 次或多次 | `*` | `*` | `*` |
| 次数区间 | `\{n,m\}` | `{n,m}` | `{n,m}` |
| 捕获分组 | `\(...\)` | `(...)` | `(...)` |
| 1 次或多次 | GNU 扩展 `\+` | `+` | `+` |
| 0 次或 1 次 | GNU 扩展 `\?` | `?` | `?` |
| 分支 | GNU 扩展，竖线前加反斜杠 | 竖线 | 竖线 |
| 模式内反向引用 | `\1` | GNU grep 扩展 `\1` | `\1` |
| `\d` | 不支持 | 不支持 | 支持 |
| `\w`、`\s`、`\b` | GNU 扩展 | GNU 扩展 | 支持 |
| 非捕获组、环视、懒惰量词 | 不支持 | 不支持 | 支持 |

> **可移植性**：`\w`、`\s`、`\b` 在 GNU grep 与 GNU sed 中可用，但不是 POSIX 通用语法，BusyBox 与 BSD/macOS 自带工具可能不支持

## 匹配什么字符

### 普通字符与点号

普通字符匹配自身，相邻书写表示按顺序匹配；`.` 匹配任意一个字符

```bash
printf '%s\n' 'cat dog cat' | grep -oE 'cat'
# cat
# cat

printf '%s\n' 'cat cot ct coat' | grep -oE 'c.t'
# cat
# cot
```

| 模式     | 可以匹配              | 不能匹配        |
|:------ |:----------------- |:----------- |
| `c.t`  | `cat`、`cot`、`c8t` | `ct`、`coat` |
| `c..t` | `coat`、`c12t`     | `cat`       |

默认只要求文本中存在匹配片段，不要求整行相等，因此 `catfish` 中的 `cat` 同样命中

grep、sed、awk 默认按行处理，`.` 不跨越行边界。需要跨行时应改变读取单位，例如 awk 的 `RS`、GNU grep 的 `-z`，而不是在模式里堆叠 `.*`

### 字符集

`[]` 表示从集合中匹配一个字符，匹配的始终是一个字符，不是整段内容

| 写法       | 含义                   |
|:-------- |:-------------------- |
| `[abc]`  | a、b、c 中的任意一个         |
| `[0-9]`  | 一个数字                 |
| `[a-z]`  | 一个小写字母               |
| `[^0-9]` | 一个非数字字符，`^` 位于首位表示取反 |
| `[^ ]`   | 一个非空格字符，制表符仍可匹配      |
| `[.]`    | 点号本身，字符集内元字符失效       |

```bash
printf '%s\n' 'name="alice" role="admin"' | grep -oE '"[^"]+"'
# "alice"
# "admin"
```

`[^"]` 限定引号内部不再出现引号，比 `.*` 更可控，原因见“贪婪与排除式”

### POSIX 字符类

字符类必须写在 `[]` 内，用来表示一类字符

| 写法                          | 含义      |
|:--------------------------- |:------- |
| `[[:digit:]]`               | 数字      |
| `[[:alpha:]]`               | 字母      |
| `[[:alnum:]]`               | 字母或数字   |
| `[[:lower:]]`、`[[:upper:]]` | 小写、大写字母 |
| `[[:space:]]`               | 空白字符    |
| `[[:blank:]]`               | 空格与制表符  |
| `[[:punct:]]`               | 标点符号    |
| `[[:xdigit:]]`              | 十六进制数字  |

`[[:alnum:]_]` 表示字母、数字或下划线；只要求 ASCII 数字时使用 `[0-9]`

locale 会影响字符分类、区间和多字节处理，可用 `locale charmap` 查看当前字符映射；只需处理 ASCII 时，可使用 `LC_ALL=C` 固定匹配环境

### 转义

下列符号在普通模式中有特殊含义，表示字面量时前置反斜杠

```
. * + ? ^ $ | ( ) [ ] { } \
```

```bash
printf '%s\n' 'a.b a+b' | grep -oE 'a\.b'    # a.b
printf '%s\n' 'a\b'     | grep -oE 'a\\b'    # a\b
```

字符集内部只有 `]`、`-`、`^`、`\` 需要处理，其余符号自动失效

| 写法            | 匹配内容       |
|:------------- |:---------- |
| `[.]`、`[*+]`  | 点号、星号或加号   |
| `[-a]`、`[a-]` | 短横线或 a     |
| `[]]`         | 右方括号，写在首位  |
| `[\^]`        | 脱字符        |
| `[\d]`        | 字母 d，不是数字类 |

只查找固定文本时，用 `-F` 关闭正则解释

```bash
printf '%s\n' 'a.b' 'axb' | grep -F 'a.b'    # a.b
```

sed 替换部分还有自己的转义规则，见“sed”

## 在 Shell 中传递正则

Shell 先完成引号解析与各类展开，再把纯文本模式交给工具。正则通常放在单引号中，避免 Shell 提前解释

| 写法 | 变量展开 | 分词 | 文件名展开 | 说明 |
|:---|:---|:---|:---|:---|
| `'...'` | 否 | 否 | 否 | 首选，模式原样传入 |
| `"..."` | 是 | 否 | 否 | 反斜杠只对特定字符生效 |
| 无引号 | 是 | 是 | 是 | `*`、`?`、`[]` 可能被展开 |
| `$'...'` | — | 否 | 否 | 可传入制表符等控制字符 |

```bash
# 错误：* 先被 Shell 展开成当前目录的文件名
grep *.log access.log

# 正确：引号阻止展开
grep '\.log$' access.log
```

字面反斜杠要经过 Shell 与正则两层

```bash
printf '%s\n' 'a\b' | grep -E 'a\\b'      # 单引号：正则收到 a\\b
printf '%s\n' 'a\b' | grep -E "a\\\\b"    # 双引号：Shell 先转义一层，结果相同
```

制表符在 GNU grep 的 BRE/ERE 中不能写 `\t`

```bash
grep $'\t' file      # 由 Bash 传入真实制表符
grep -P '\t' file    # 由 PCRE 解释
```

## 匹配几次

### 量词

量词修饰紧邻的前一个单位，这个单位可以是字符、字符集或分组

| 量词      | 次数       | 示例           | 可以匹配         |
|:------- |:-------- |:------------ |:------------ |
| `*`     | 0 次或多次   | `ab*`        | a、ab、abbb    |
| `+`     | 1 次或多次   | `ab+`        | ab、abbb      |
| `?`     | 0 次或 1 次 | `colou?r`    | color、colour |
| `{n}`   | 恰好 n 次   | `[0-9]{4}`   | 四位数字         |
| `{n,}`  | 至少 n 次   | `[0-9]{2,}`  | 至少两位数字       |
| `{n,m}` | n 到 m 次  | `[0-9]{2,4}` | 两至四位数字       |

BRE 中 `+`、`?`、`{}` 需要转义，写法见“选择正则方言”

### 作用范围

| 模式      | 量词修饰 | 含义               |
|:------- |:---- |:---------------- |
| `ab+`   | b    | 一个 a 后跟至少一个 b    |
| `[ab]+` | 字符集  | 一个以上 a 或 b，可任意混合 |
| `(ab)+` | 分组   | ab 整体至少出现一次      |

```bash
printf '%s\n' 'abbb'   | grep -oE 'ab+'      # abbb
printf '%s\n' 'ababab' | grep -oE '(ab)+'    # ababab
```

优先级从高到低为：**量词 → 连接 → 分支**

| 表达式           | 实际含义              |
|:------------- |:----------------- |
| `ab\|cd`      | ab 或 cd           |
| `a(b\|c)d`    | a 后跟 b 或 c，再跟 d   |
| `^yes\|no$`   | 以 yes 开头，或以 no 结尾 |
| `^(yes\|no)$` | 整行为 yes 或 no      |

```bash
printf '%s\n' 'yes' 'no' 'yesterday' | grep -E '^(yes|no)$'
# yes
# no
```

连接优先于分支，因此 `ab|cd` 不需要括号；需要把分支限制在表达式的一部分时才加括号；锚点只约束它所在的那一支，`^yes|no$` 的两个锚点分属两支

多个分支都能匹配时，结果还取决于引擎：POSIX 采用最左最长规则，PCRE 按分支顺序尝试并可能回溯

```bash
printf '%s\n' 'abc' | grep -oE 'ab|abc'   # abc，POSIX 取最长
printf '%s\n' 'abc' | grep -oP 'ab|abc'   # ab，PCRE 取首个成功者
```

### 空匹配

`*`、`?`、`{0,n}` 允许前面的单位不出现，模式因此可以匹配空字符串

```bash
printf '%s\n' 'abc' | grep -E '[0-9]*'    # abc，空匹配也算该行命中
printf '%s\n' 'abc' | grep -o '[0-9]*'    # 无输出，-o 不输出空匹配
```

| 需求     | 写法         |
|:------ |:---------- |
| 至少有数字  | `[0-9]+`   |
| 整行都是数字 | `^[0-9]+$` |
| 数字可以没有 | `^[0-9]*$` |

```bash
v=""
[[ $v =~ ^[0-9]*$ ]] && echo 通过    # 通过，空串满足 0 次
[[ $v =~ ^[0-9]+$ ]] || echo 拒绝    # 拒绝，+ 要求至少一次
```

校验“必须填写”时使用 `+` 或 `{1,}`，`*` 只用于表示可选

### 贪婪与排除式

`.*` 会一直匹配到最后一个可行位置

```bash
printf '%s\n' '"alice" and "bob"' | grep -oE '".*"'
# "alice" and "bob"
printf '%s\n' '"alice" and "bob"' | grep -oE '"[^"]*"'
# "alice"
# "bob"
```

`[^"]*` 允许空内容，`[^"]+` 要求至少一个字符；PCRE 的懒惰量词见“懒惰量词”

## 匹配在哪里

位置类写法不消耗字符，只判断某个位置是否成立，因此可以叠加，也不会出现在 `-o` 的输出中

### 锚点

| 模式      | 条件       | 可以匹配             |
|:------- |:-------- |:---------------- |
| `cat`   | 任意位置包含   | cat、scat、catfish |
| `^cat`  | 以 cat 开头 | cat、catfish      |
| `cat$`  | 以 cat 结尾 | cat、scat         |
| `^cat$` | 整行只有 cat | cat              |

`^cat$` 的匹配内容是 `cat`，其中没有额外的“行首字符”或“行尾字符”

### 空行与空白行

| 模式               | 含义            |
|:---------------- |:------------- |
| `^$`             | 真正的空行，长度为零    |
| `^[[:space:]]*$` | 空行，或只包含空白字符的行 |

```bash
printf 'text\n\n \n' | grep -c '^$'              # 1
printf 'text\n\n \n' | grep -c '^[[:space:]]*$'  # 2
```

### 词边界

`\b` 表示单词字符与非单词字符之间的位置，`\B` 表示相反情况

```bash
printf '%s\n' 'cat scatter catfish' | grep -oE '\bcat\b'    # cat
```

连字符属于非单词字符，因此 `\bnginx\b` 仍会命中 `nginx-proxy` 中的 nginx，词边界不等于业务上的“完整名称”

```bash
printf '%s\n' 'nginx-proxy nginx' | grep -oE '(^|[^[:alnum:]_-])nginx($|[^[:alnum:]_-])'
# 只命中独立的 nginx，但会连带前导分隔符，需要裁剪
```

### 整词与整行

| 目标   | 写法                  | 说明             |
|:---- |:------------------- |:-------------- |
| 整词匹配 | `-w` 或 `\b...\b`    | 边界成立即可，不要求整行相等 |
| 整行匹配 | `grep -x` 或 `^...$` | 整行内容必须与模式完全一致  |

```bash
printf '%s\n' 'abc abc' | grep -cx 'abc'     # 0，整行不等于 abc
printf '%s\n' 'abc abc' | grep -c -w 'abc'   # 1，按行统计，行内两个词都命中
```

## 分组与捕获

### 分组

`( )` 把若干单位合成一个整体，解决三件事：让量词作用于整段、限定分支范围、记录匹配内容

前面的 `(ab)+`、`a(b|c)d` 已经用到前两种，第三种是下一节的捕获

### 捕获与编号

普通括号除了分组，还会记录本次匹配到的文本，这个过程称为捕获

以 `([0-9]{4})-([0-9]{2})-([0-9]{2})` 匹配 `2026-11-03` 为例

| 项目    | 对应模式         | 捕获文本       |
|:----- |:------------ |:---------- |
| 整体匹配  | 完整表达式        | 2026-11-03 |
| 第 1 组 | `([0-9]{4})` | 2026       |
| 第 2 组 | `([0-9]{2})` | 11         |
| 第 3 组 | `([0-9]{2})` | 03         |

括号里是规则，捕获结果是文本。同一模式匹配不同输入时，捕获结果随之改变

编号从 1 开始，按左括号出现的顺序分配；嵌套时外层左括号先出现，先获得编号

以下示例在 Bash 中执行，`[[ =~ ]]` 匹配成功后会把结果写入 `BASH_REMATCH`

```bash
v=abcd
[[ $v =~ ((a)(b))(cd) ]]

# 第 0 组是整个匹配，第 1 到 4 组按左括号顺序排列
echo "${BASH_REMATCH[0]} ${BASH_REMATCH[1]} ${BASH_REMATCH[2]} ${BASH_REMATCH[3]} ${BASH_REMATCH[4]}"
# abcd ab a b cd
```

### 重复分组保存什么

重复的是同一个组，不会每重复一次就新增编号，组内只保留最后一次捕获

```bash
v="12,34,"
[[ $v =~ ([0-9]+,)+ ]]

echo "${BASH_REMATCH[0]} 与 ${BASH_REMATCH[1]}"
# 12,34, 与 34,，第 1 组只剩最后一次捕获
```

需要逐项结果时，应拆分文本，或用 `grep -o` 分别匹配各段

### 非捕获组

`(?: )` 只分组，不分配捕获编号

| 写法         | 量词作用 | 捕获情况           |
|:---------- |:---- |:-------------- |
| `(abc)+`   | 整段   | 组 1 保存最后一次 abc |
| `(?:abc)+` | 整段   | 不产生捕获          |

```bash
printf '%s\n' 'abcabc' | grep -cP '(?:abc)+'    # 1
printf '%s\n' 'abcabc' | grep -cE '(?:abc)+'    # 0，ERE 不支持
```

适用场景是只需要限定范围、不打算取值，避免捕获编号错位。`(?: )` 属于 PCRE，`grep -E`、`sed -E`、`[[ =~ ]]` 都会失败或静默不匹配

### 反向引用

`\1` 要求后续文本与第 1 组捕获的内容相同，不是重新执行第 1 组的规则

```bash
printf '%s\n' 'abc abc' 'abc def' | grep -E '^([a-z]+) \1$'
# abc abc
```

| 模式                    | 条件             |
|:--------------------- |:-------------- |
| `^([a-z]+) ([a-z]+)$` | 两段分别由字母组成，可以不同 |
| `^([a-z]+) \1$`       | 第二段必须与第一段相同    |

分组范围写错时引用就错位

```bash
# 错误：\1 指向 ([0-9]{1,3}\.)，重复三次只保留最后一次的 3.
echo '1.2.3.4 1.2.3.4' | grep -E '([0-9]{1,3}\.){3}[0-9]{1,3} \1'
# 无输出

# 把 \1 换成它实际捕获的文本，结果相同：空格后面要求再跟一个 3.
echo '1.2.3.4 1.2.3.4' | grep -E '([0-9]{1,3}\.){3}[0-9]{1,3} 3\.'
# 无输出

# 正确：外层分组包住完整地址，\1 才是整串 IP
echo '1.2.3.4 1.2.3.4' | grep -E '(([0-9]{1,3}\.){3}[0-9]{1,3}) +\1'
# 1.2.3.4 1.2.3.4
```

ERE 中的反向引用属于 GNU grep 扩展，awk 正则不支持

### 三种取值方式

| 场景      | 写法                   | 由谁解释 | 得到的内容           |
|:------- |:-------------------- |:---- |:--------------- |
| 模式内反向引用 | `\1`                 | 正则引擎 | 已捕获文本，继续参与匹配    |
| sed 替换  | `\1`、`&`             | sed  | 已捕获文本、整个匹配，写入输出 |
| Bash 赋值 | `${BASH_REMATCH[1]}` | Bash | 已捕获文本，作为变量值     |

`grep -o` 不在此列，它始终输出整个匹配，捕获组不会改变输出

## 使用匹配结果

| 工具   | 默认输出         | 只输出匹配                  | 如何取分组              |
|:---- |:------------ |:---------------------- |:------------------ |
| grep | 整个匹配行        | `-o` 输出整个匹配            | 不能，需 `\K` 或 sed    |
| sed  | 处理后的整行       | `-n` 配合 `p`            | 替换部分写 `\1`、`&`     |
| awk  | 由 `print` 决定 | `match()` + `substr()` | gawk 三参数 `match()` |
| Bash | 不产生输出        | —                      | `BASH_REMATCH[n]`  |

### grep

| 目标      | 写法         |
|:------- |:---------- |
| 只输出匹配片段 | `grep -oE` |
| 整行匹配    | `grep -xE` |
| 整词匹配    | `grep -wE` |
| 统计命中行数  | `grep -cE` |
| 反向筛选    | `grep -vE` |
| 忽略大小写   | `grep -iE` |
| 仅判断有无   | `grep -qE` |
| 按字面量匹配  | `grep -F`  |

`-o` 输出的始终是整个匹配，捕获组不会自动出现

```bash
echo 'ip=192.168.0.1' | grep -oE 'ip=[0-9.]+'      # ip=192.168.0.1
echo 'ip=192.168.0.1' | grep -oP 'ip=\K[0-9.]+'    # 192.168.0.1
```

`-c` 统计行数，`-o` 配合 `wc -l` 统计次数

```bash
printf '%s\n' 'error error error' | grep -c 'error'            # 1
printf '%s\n' 'error error error' | grep -o 'error' | wc -l    # 3
```

`grep -q` 常见于脚本判断：退出码 0 表示命中，1 表示未命中，2 表示执行出错

### sed

匹配部分使用 ERE 时加 `-E`，替换部分是 sed 自己的语法

```bash
printf '%s\n' '2026-11-03' | sed -E 's/^([0-9]{4})-([0-9]{2})-([0-9]{2})$/\3\/\2\/\1/'
# 03/11/2026

printf '%s\n' '2026-11-03' | sed -E 's#^([0-9]{4})-([0-9]{2})-([0-9]{2})$#\3/\2/\1#'
# 03/11/2026

printf '%s\n' 'user=alice' 'invalid' | sed -nE 's/^user=([[:alnum:]_]+)$/\1/p'
# alice
```

| 替换部分写法    | 含义            |
|:--------- |:------------- |
| `&`       | 整个匹配          |
| `\&`      | 字面量 &         |
| `\1`–`\9` | 对应分组的内容       |
| `\\`      | 一个字面反斜杠       |
| `/`       | 分隔符，需转义或更换分隔符 |

默认输出处理后的整行，`-n` 关闭默认输出，`p` 只打印替换成功的行

### awk

`~` 表示匹配，`!~` 表示不匹配，正则可写成 `/模式/` 或字符串

```bash
printf '%s\n' 'alice 200' 'bob 500' | awk '$2 ~ /^5[0-9]{2}$/ {print $1}'
# bob
```

需要按位置提取片段时用 `match()`，它返回起始位置，并设置 `RSTART` 与 `RLENGTH`

```bash
printf '%s\n' 'user=alice id=123' | awk '{
    if (match($0, /[0-9]+/))
        print substr($0, RSTART, RLENGTH)
}'
# 123
```

gawk 支持三参数形式，把捕获组放入数组；该写法不能假设所有 awk 都支持

```bash
printf '%s\n' '2026-11-03' | awk '{
    match($0, /([0-9]{4})-([0-9]{2})-([0-9]{2})/, a)
    print a[1], a[2], a[3]
}'
# 2026 11 03
```

awk 只提供 ERE，没有 `\b`。`/.../` 是正则常量；模式写成字符串时，还要经过 awk 的字符串解析，因此需要多一层转义

```bash
awk '$1 ~ /^192\.168\./' access.log
awk '$1 ~ "^192\\.168\\."' access.log
```

### Bash

```bash
value='2026-11-03'
pattern='^([0-9]{4})-([0-9]{2})-([0-9]{2})$'

if [[ $value =~ $pattern ]]; then
    printf '年 %s 月 %s 日 %s\n' \
        "${BASH_REMATCH[1]}" "${BASH_REMATCH[2]}" "${BASH_REMATCH[3]}"
fi
# 年 2026 月 11 日 03
```

模式存入变量后写 `$pattern`；写成 `"$pattern"` 会退化为字面文本匹配。`[[ ]]` 内部不进行分词和文件名展开，这一点与 `[ ]` 不同

### 文件名匹配

`-name` 使用 glob，`-regex` 使用正则并匹配完整路径

```bash
find /var/log -name '*.log'
find /var/log -regextype posix-extended -regex '.*\.(log|gz)$'
```

`*.log` 属于 glob，`*` 独立表示任意长度字符；正则中的 `*` 是量词，必须前置单位，`grep '*.log'` 匹配的是以字面量 `*` 开头的行

## PCRE 按需使用

`grep -P` 提供 PCRE 方言，本节语法不能套入 `grep -E`、`sed -E` 或 `[[ =~ ]]`

### 简写字符类

| 写法        | 含义         | 说明                         |
|:--------- |:---------- |:-------------------------- |
| `\d`、`\D` | 数字、非数字     | 仅 PCRE 提供，`grep -E` 不识别    |
| `\w`、`\W` | 单词字符、非单词字符 | GNU grep 的 BRE/ERE 也支持，属扩展 |
| `\s`、`\S` | 空白、非空白     | 同上                         |

需要可移植时改用 `[0-9]`、`[[:alnum:]_]`、`[[:space:]]`

### 懒惰量词

量词后加 `?` 表示优先尝试较少的次数，如 `*?`、`+?`、`??`

```bash
printf '%s\n' '<a><b>' | grep -oP '<.*>'     # <a><b>
printf '%s\n' '<a><b>' | grep -oP '<.*?>'    # <a>、<b> 两行
```

`<[^>]*>` 也能逐段匹配，但排除式与懒惰式表达的条件不同，不能无条件互换

### 环视

环视检查当前位置左右是否满足某个模式，检查部分不计入匹配结果

| 写法         | 名称   | 条件        |
|:---------- |:---- |:--------- |
| `(?=...)`  | 正向先行 | 右侧满足指定模式  |
| `(?!...)`  | 负向先行 | 右侧不满足指定模式 |
| `(?<=...)` | 正向后行 | 左侧满足指定模式  |
| `(?<!...)` | 负向后行 | 左侧不满足指定模式 |

```bash
printf '%s\n' '12元 8.5元' | grep -oP '[0-9]+(?:\.[0-9]+)?(?=元)'
# 12
# 8.5
printf '%s\n' 'user=alice role=admin' | grep -oP '(?<=user=)[[:alnum:]_]+'
# alice
```

后行断言通常要求定长，PCRE2 10.43 起支持部分有明确长度上限的可变长写法，实际能力取决于版本

### \K 与命名组

`\K` 丢弃左侧已匹配的内容，只输出右侧部分

```bash
printf '%s\n' '/api/order?userid=8&id=9' | grep -oP '[?&]id=\K[0-9]+(?=&|$)'
# 9
```

`[?&]id=` 用来排除 `userid` 这类同后缀参数

命名组写作 `(?<name>...)`，用 `\k<name>` 反向引用；grep 不会按名称单独输出捕获内容，主要用于脚本语言的取值

### 回溯控制

原子分组 `(?>...)` 与占有量词 `*+`、`++`、`?+` 可以阻止局部回溯，但会改变匹配语义

```bash
printf '%s\n' 'aaa' | grep -oP 'a+a'     # aaa
printf '%s\n' 'aaa' | grep -oP 'a++a'    # 无输出，a++ 不交还字符
```

它们只控制局部回溯，不能保证消除整个模式的性能问题

性能上优先限定字符范围与输入长度，固定文本用 `-F`；嵌套量词与含混分支容易产生大量回溯

## 组合一条完整表达式

构造顺序：选字符 → 定次数 → 拼分支 → 加边界 → 查反例

> **验证顺序**：先用 `printf` 构造最小样本，确认输出与预期一致，再应用到生产数据

### 日期

目标：整行形如 `2026-11-03`，年固定四位，月 01–12，日 01–31

| 部分  | 模式                           | 说明                  |
|:--- |:---------------------------- |:------------------- |
| 年   | `[0-9]{4}`                   | 四位数字                |
| 分隔符 | `-`                          | 字面短横线               |
| 月   | `(0[1-9]\|1[0-2])`           | 01–09 或 10–12       |
| 日   | `(0[1-9]\|[12][0-9]\|3[01])` | 01–09、10–29 或 30–31 |
| 边界  | `^`、`$`                      | 要求整行符合模式            |

```text
^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$
```

```bash
printf '%s\n' '2026-11-03' '2026-13-03' '2026-02-31' |
    grep -E '^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$'
# 2026-11-03
# 2026-02-31
```

该模式限制月与日各自的取值范围，但不检查大小月与闰年，`2026-02-31` 依然通过；需要真实校验时追加一步

```bash
d="2026-02-31"
[[ $d =~ ^[0-9]{4}-(0[1-9]|1[0-2])-(0[1-9]|[12][0-9]|3[01])$ ]] &&
    date -d "$d" +%F >/dev/null 2>&1 && echo 有效 || echo 无效
# 无效
```

### IPv4

难点是单段的 0–255，按数值区间拆成互斥分支

| 区间      | 模式            | 说明           |
|:------- |:------------- |:------------ |
| 250–255 | `25[0-5]`     | 百位 25，个位 0–5 |
| 200–249 | `2[0-4][0-9]` | 十位 0–4       |
| 100–199 | `1[0-9]{2}`   | 百位 1         |
| 0–99    | `[1-9]?[0-9]` | 十位可选，排除前导 0  |

前三段共用一份子模式并重复三次，最后一段单独书写

```bash
IP='(25[0-5]|2[0-4][0-9]|1[0-9]{2}|[1-9]?[0-9])'
grep -E "^(${IP}\.){3}${IP}$" <<< '192.168.0.1'    # 命中
grep -E "^(${IP}\.){3}${IP}$" <<< '256.1.1.1'      # 无输出
grep -E "^(${IP}\.){3}${IP}$" <<< '01.2.3.4'       # 无输出
```

该模式只判断格式，不判断地址类型；只需从日志里提取地址时，用宽松式 `([0-9]{1,3}\.){3}[0-9]{1,3}` 即可

### 日志字段

以 nginx 默认格式为例

```text
192.168.0.10 - - [03/Nov/2026:10:12:33 +0800] "GET /api/user HTTP/1.1" 200 512
```

字段位置固定时优先用 awk 切分

```bash
awk '{print $1, $7, $9}' access.log
# 192.168.0.10 /api/user 200
```

需要同时校验结构时，用正则整行拆解

| 片段                        | 作用                 |
|:------------------------- |:------------------ |
| `^(\S+)`                  | 客户端 IP，非空白序列       |
| ` \S+ \S+ `               | ident 与 user，占位不捕获 |
| `\[([^]]+)\]`             | 方括号内的时间            |
| `"(\S+) ([^ ]+) ([^"]*)"` | 方法、路径、协议           |
| ` (\d{3})`                | 状态码                |
| ` (\d+)$`                 | 响应大小               |

各片段按顺序相连即得完整模式

```bash
grep -oP '^(\S+) \S+ \S+ \[([^]]+)\] "(\S+) ([^ ]+) ([^"]*)" (\d{3}) (\d+)$' access.log
# 整行输出，分组不单独显示
```

只取单个字段时配合 `\K`，输出更干净

```bash
grep -oP '^\K\S+' access.log            # 192.168.0.10
grep -oP '"\S+ \K[^ ]+' access.log      # /api/user
grep -oP '" \K\d{3}' access.log         # 200
```

`[^]]+` 用排除式限定时间，避免 `.*` 越过 `]`；字段顺序或分隔符变化时整条模式失效
